# Ant Design evaluation — Phase 1

Evaluated against the installed stable Ant Design release recorded in the lockfile. Evidence: CRM browser tests, Storybook production build and real screenshots. This is a small synthetic dataset (48 clients), not a large-data benchmark.

| Capability                  | POC finding and evidence                                                                                                                                            | Workaround / Phase 2 decision                                                                                                                                                                                      |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Advanced table interactions | Native sorting, selection, pagination and empty states work. Search and combined filters are controlled outside Table. CSV exports the filtered set.                | Keep Ant Design; introduce controlled server queries only with a backend contract.                                                                                                                                 |
| Column resizing             | No turnkey resizable header API. POC supplies labeled native range inputs in headers, allowing keyboard resizing from 100–380px. Browser test changes wallet width. | Small custom adapter is sufficient for POC. Evaluate pointer handles with drag cancellation and min/max constraints in Phase 2.                                                                                    |
| Column reordering           | No built-in column ordering UI. POC column popover has move-left buttons and visibility checkboxes. Client identity stays pinned.                                   | Keep explicit keyboard controls. Consider dnd-kit for optional drag gestures, never a second full UI framework.                                                                                                    |
| Fixed columns               | Native `fixed: left` works for client identity with horizontal overflow; selection remains available.                                                               | Define pinned width budgets; test zoom and two-sided pinning before adding more fixed columns.                                                                                                                     |
| Responsive tables           | Horizontal scroll preserves financial precision on narrow screens. Mobile test exercises combined filters and empty state.                                          | Native responsive hiding is available but can conceal important facts. Add opt-in priority columns or a custom card presentation after user research.                                                              |
| Complex editable forms      | Form rules, required fields, email format, enums and bounded numeric amounts work in the large modal; save updates the table.                                       | POC uses a record editor rather than inline cells. Nested arrays, conditional fields and async validation still need dedicated evaluation. Use Ant Form.List first.                                                |
| Large modals                | 760px modal renders responsive form fields, inherited colors, validation, save/cancel and contextual demo notice.                                                   | Inline container preserves CSS variables. Test long content, focus restoration and nested overlays with assistive technology. Prefer a full page for workflows with extensive history.                             |
| Compact layouts             | Ant compact algorithm plus token-driven controls and table padding work in dark mode (screenshot).                                                                  | Avoid smaller pointer targets for touch-first layouts; separate touch sizing if product research requires it.                                                                                                      |
| Theming                     | Both modes and density compose through ConfigProvider. Table, Button and Modal support targeted overrides.                                                          | Semantic tokens still need a mapping layer; portal scope is explicit. Avoid targeting generated class hashes.                                                                                                      |
| Large data / virtualization | Not benchmarked. Native pagination limits this POC to six visible rows.                                                                                             | Benchmark native virtual Table at 10k+ rows with resizing and pinned columns before deciding on TanStack Table/Virtual. A headless replacement is justified only if measured constraints outweigh native behavior. |

Other limits: column preferences, edits and theme settings are not persisted; resize is a POC range control rather than a professional drag handle; trend percentages/sparklines are illustrative; no live prices, trading, balances ledger, permissions, audit logging, backend or timezone-localized monetary workflows. USD display is formatting of synthetic numbers, not monetary accounting logic.

Phase 2 priorities: accessibility audit and automated axe coverage; package boundary and tree shaking; responsive/touch research; expanded component stories and interaction tests; locale/RTL and multi-currency formats; validated data-grid performance; preference persistence; visual regression tests; API governance and release policy.
