# Real application screenshots

Run `npm run build` and `npm run test:e2e` with Chromium installed. Tests take
screenshots through the running Vite application; they also run keyboard and axe
checks. Most desktop captures use 1536×1120, tablet 1024×900, mobile 390×844.

- `tokens-{light,dark}.png`: palette, typography and layout foundations.
- `components-{light,dark}.png`: buttons, forms and core gallery.
- `financial-{light,dark}.png`: synthetic financial dashboard composition.
- `crm-*.png`, `compact-grid.png`: working CRM and density variants.
- `library-{light,dark}.png`: complete Phase 2 public documentation.
- `library-financial-{light,dark}.png`: reusable financial package components.
- `library-grid.png`: synthetic 10k-row paginated DataGrid.
- `library-mobile.png`, `mobile.png`, `mobile-navigation.png`: narrow screen examples.

Files not regenerated by current assertions (older `showcase-*` captures) are
retained Phase 1 evidence. Browser rendering and font versions can change pixels;
these are review evidence, not pixel-perfect baseline assertions.

## App shell regression captures

`shell-{desktop,tablet,mobile,short,mobile-landscape}-{light,dark}.png` capture
aligned headers, sidebar and viewport-bound main content. Drawer captures use
`shell-drawer-{mobile,mobile-landscape}-{light,dark}.png`. See
[layout behavior and viewport dimensions](../shell-refinement.md).

The shell now scrolls inside `.main-scroll`; full-page browser screenshots capture
the viewport-bound shell. Section-specific captures still scroll the relevant
section into view. Use the running application to inspect content beyond the
visible viewport.

Phase 3: `iconography-light-chromium.png`, `iconography-dark-chromium.png` and
`iconography-mobile.png` are real Playwright Chromium captures of searchable
iconography and size/stroke/tone customization. Engine-specific CI captures are
uploaded as workflow artifacts. See `../phase-three-report.md` for limitations.
